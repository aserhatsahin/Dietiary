# Deploying the demo API

The public demo runs on **Render** (free web service, Docker) with a **Neon** database (free PostgreSQL that does not expire). Render reads the service definition from [`render.yaml`](../render.yaml). This guide covers the one-time setup; after that, every merge to `main` that touches the backend deploys automatically once CI passes.

What it costs: nothing. The free plans' limits are below.

## 1. Create the database on Neon

1. Sign up at [neon.com](https://neon.com) (GitHub login works).
2. Create a project:
   - **Name:** `dietiary`
   - **Postgres version:** 18 (or the newest offered)
   - **Region:** AWS Europe Central 1 (Frankfurt), the same region as the Render service
3. Open **Connect** on the project dashboard. Turn **Connection pooling off**: Flyway migrations need a direct connection. Then copy these parts of the connection string:

   ```
   postgresql://<user>:<password>@<host>/<database>?sslmode=require
   ```

4. Turn them into the three values Render needs:

   | Render variable | Value |
   |---|---|
   | `SPRING_DATASOURCE_URL` | `jdbc:postgresql://<host>/<database>?sslmode=require` |
   | `SPRING_DATASOURCE_USERNAME` | `<user>` |
   | `SPRING_DATASOURCE_PASSWORD` | `<password>` |

   The JDBC URL has no user or password in it. Keep the password out of the repo, chats and screenshots.

## 2. Create the service on Render

1. Sign up at [render.com](https://render.com) with GitHub and allow access to the `Dietiary` repository.
2. **New > Blueprint**, then pick the `Dietiary` repository. Render finds `render.yaml` and shows the `dietiary-api` service.
3. Render asks for the three values marked `sync: false`. Paste the values from step 1.4. `JWT_SECRET` is generated by Render; leave it alone.
4. Click **Apply** / **Deploy Blueprint**.

The first deploy takes roughly 10 minutes:
- building the image: about 5 minutes
- starting on 0.1 CPU: about 2–3 minutes
- creating the demo data: about 1–2 minutes

The service is live when its status turns green.

## 3. Check it

Replace the URL with the one Render shows (for example `https://dietiary-api.onrender.com`):

```bash
curl https://dietiary-api.onrender.com/actuator/health
```

You should get `{"status":"UP"...}`. Then open `https://dietiary-api.onrender.com/swagger-ui.html` and log in with the demo account from the [README](../README.md#live-demo).

## 4. Keep it awake (recommended)

Free Render services stop after 15 minutes without traffic. Starting again takes 2–3 minutes, so a visitor would wait that long. The [`Keep demo warm`](../.github/workflows/keep-demo-warm.yml) workflow calls the health endpoint every 10 minutes. One always-on service fits within Render's 750 free hours a month.

To turn it on: in GitHub, open **Settings > Secrets and variables > Actions > Variables > New repository variable**, with name `DEMO_API_URL` and the service URL as the value (no trailing slash). You can run it once by hand from the **Actions** tab to test it.

## Free plan limits

| | Limit |
|---|---|
| Render web service | 0.1 CPU, 512 MB RAM; stops after 15 min idle; 750 instance hours/month |
| Neon database | 1 GB storage; 100 compute hours/month; the database itself sleeps after 5 min idle and wakes in under a second |

The app is tuned for this: about 290 MB of memory in use, a heap capped at 60%, and a class-data-sharing archive built into the image to shorten startup. These limits are fine for a demo, not for real clients' data.

## Later changes

- **New backend code:** merge to `main`. Render deploys after the CI checks pass (`autoDeployTrigger: checksPass`) and only when `backend/` or `render.yaml` changed.
- **Web panel URL:** when the panel is deployed, add its origin to `CORS_ALLOWED_ORIGINS` in `render.yaml` (comma-separated). Values marked `sync: false` are not touched by later Blueprint syncs.
- **Demo data:** it is created once, on the first start with an empty database. To start over, delete the Neon branch's data (or the project) and redeploy.
